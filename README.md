# Credit Risk Modelling Using Machine Learning

End-to-end credit risk classification on the **German Credit (Statlog)** dataset: EDA, a leak-free preprocessing
pipeline, benchmarked and tuned models, repeated cross-validation, cost-sensitive decision threshold, SHAP
explainability, and a Streamlit app that returns a risk probability with a per-applicant explanation.

## Key results

Positive class = **bad** credit risk (30% of the 1,000 applicants).

| Model | Test ROC-AUC | Repeated-CV AUC (5x3) | Recall (bad) @0.5 | Brier |
|---|---|---|---|---|
| **Random Forest (selected)** | **0.877** | **0.776 ± 0.031** | 0.883 | 0.171 |
| Extra Trees | 0.854 | 0.752 ± 0.033 | 0.883 | 0.182 |
| XGBoost | 0.846 | 0.762 ± 0.029 | 0.783 | 0.169 |
| Logistic Regression | 0.837 | 0.754 ± 0.032 | 0.833 | 0.184 |
| Decision Tree | 0.795 | 0.706 ± 0.026 | 0.817 | 0.189 |
| Dummy baseline | 0.500 | 0.500 | 0.000 | 0.210 |

- **Use the repeated-CV AUC (about 0.78) as the headline figure.** The 0.877 test AUC comes from a single
  200-row split (60 bad cases) and is optimistic; the 5x3 repeated CV on all 1,000 rows is the more reliable estimate.
- The tuned Random Forest ranks first on both measures, but the gap to XGBoost and Logistic Regression is within
  about one standard deviation, so treat the ranking as indicative rather than definitive.
- At the default 0.5 cut-off the model catches **88% of bad applicants** (precision 59%, 7 bad approved out of 60).

### Cost-sensitive threshold
The Statlog documentation states that approving a bad applicant costs **5x** rejecting a good one. The threshold
was chosen by minimising that cost on out-of-fold training predictions only (result: **0.40**). On the held-out
test set, 0.40 lifted recall on bad applicants from 88.3% to 91.7% but rejected more good applicants (61 vs 37), so
total cost was slightly *higher* (86 vs 72). With only 60 bad cases in the test set that difference is within noise.
The 0.40 threshold is kept in the app because it was selected on training data without peeking at the test set.

### What drives the predictions (SHAP and permutation importance)
Checking-account status is by far the strongest feature, followed by loan duration, credit amount and
savings-account status. Longer, larger loans raise risk. Applicants with no checking account are modelled as
*lower* risk, which is a known characteristic of this dataset (the "no account" group has the lowest default rate)
and not a causal statement.

## Improvements over the first version
| Before | Now |
|---|---|
| Dropped every row with a missing account (478 of 1,000 rows) | Kept all rows; `NA` = **"no account"**, an informative category |
| Accuracy-only model selection | ROC-AUC, PR-AUC, recall/precision on *bad*, Brier score, repeated CV |
| No baseline | Dummy and Logistic Regression baselines |
| Label-encoding categoricals | One-hot encoding inside an sklearn `Pipeline` (no leakage) |
| Default 0.5 cut-off | Cost-based threshold using the 5:1 Statlog cost matrix |
| No explainability | SHAP (global + per applicant) and permutation importance |
| Many pickles + app duplicating encoding | One `credit_risk_model.joblib`; shared `credit_utils.py` |
| Added `Credit per month` feature | Repayment-burden proxy (amount / duration) |

## Data
German Credit (Statlog) data, Hofmann (1994), UCI Machine Learning Repository, in the readable Kaggle
version (`Age, Sex, Job, Housing, Saving accounts, Checking account, Credit amount, Duration, Purpose, Risk`).
1,000 applicants, 700 good / 300 bad.

## Limitations
- Small, old (1994) dataset: results will not transfer directly to a modern portfolio.
- Single 200-row test split is noisy; confidence intervals on the metrics are wide (CV std about 0.03 AUC).
- `Sex` and `Age` are included as features. This is for demonstration; in real lending they raise
  fairness and regulatory concerns and would be reviewed or excluded.
- No out-of-time validation, as the data has no dates.
- Not for real credit decisions.
